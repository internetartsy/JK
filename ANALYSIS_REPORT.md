# Codebase Analysis Report

## 1. Bundle & Duplicate Files
The following files/directories were identified as generated bundles or potential duplicates:

- **`frontend/dist/`**: The production build output of the frontend. NOT a source folder. Should be gitignored (already is likely).
- **`manifest.json`**: Generated by Vite PWA plugin in `dist/`.

## 2. Non-Dependency / Junk Files (Cleaned Up)
The following files appeared to be temporary test scripts or artifacts and have been **deleted**:

- `backend/cookies.txt`: Temporary file likely from curl/wget.
- `backend/verify_hybrid_integration.py`: One-off verification script.
- `backend/test_tile_server.py`: Ad-hoc test script.

## 3. Code & Logic Issues

### 🔴 Critical: Frontend <-> Backend Model Mismatch
- **File**: `frontend/src/App.tsx` vs `backend/app/models/land_parcel.py`
- **Issue**: The frontend assumed `LandParcel` had an `owner_id` field to calculate "Total Farmers".
- **Reality**: The backend `LandParcel` model DOES NOT have an `owner_id` or `owners` relationship loaded in the main list endpoint (`/parcels/`).
- **Fix Applied**: Frontend `App.tsx` has been patched to hardcode `totalFarmers: 0` with a TODO comment to prevent runtime errors.
- **Recommendation**: Update `LandParcel` model in backend to support owner relationships, or create a separate endpoint for farmer statistics.

### 🟡 Warning: Mobile Native Dependencies
- **File**: `mobile/src/services/OCRService.ts`
- **Status**: Contains a conditional require for `react-native-mlkit-ocr`.
- **Note**: This will CRASH if run in Expo Go without the `catch` block (which is present). Ensuring `eas build` is used for testing this feature is critical.

### 🟢 Good Practices Found
- **Vite Config**: `frontend/vite.config.ts` correctly uses `manualChunks` to split large libraries (`maplibre-gl`, `tesseract.js`) from the main bundle.
- **Redis Caching**: `backend/app/core/redis.py` and `geo.py` correctly implement caching for expensive tile manifest generation.
- **PostGIS**: Spatial indexes have been added via Alembic migration (`ea6afb513648_add_spatial_indexes.py`).
